# Documentation policy

- User guides: prerequisites, commands and essential caveats only.
- Architecture: concise ownership and design decisions.
- Roadmap: unfinished work, not a duplicate feature inventory.
- ADRs and historical investigations: keep in reference/history.
- Generate command, alias, keybinding and tool references from source.
- Do not duplicate safeguards or implementation details across pages.
- Update relevant docs when behaviour changes; run the strict documentation build.
